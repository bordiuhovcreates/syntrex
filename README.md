# Стартовий шаблон VERSTAI

Готовий каркас лендингу, в якому вся технічна частина вже налаштована. Ви підставляєте свій макет — Claude збирає блоки на правильній основі. Шаблон можна використовувати для кожного наступного проєкту.

## Що вже налаштовано

| | |
|---|---|
| **Структура** | Astro, кожен блок в окремому компоненті (`Block1`, `Block2`…), тексти й картинки у файлах контенту |
| **CLAUDE.md** | правила для Claude: структура, змінні, адаптив, анімації, економія токенів |
| **Стилі** | `variables.css` із заготовками кольорів, стилів тексту й відступів, скидання стилів, контейнер, кнопка |
| **Анімації** | GSAP: поява при скролі, поява карток по черзі, лічильники цифр — вмикаються одним атрибутом |
| **Інтерактив** | бургер-меню, плавний скрол до блоків, FAQ-акордеон, попап з формою |
| **Форма заявок** | форма з перевіркою полів і пасткою від спаму + готовий Google Apps Script → Telegram і Google-таблиця |
| **Адмінка** | `.pages.yml` для Pages CMS: усі тексти, контакти, списки й фото підписані українською |
| **Публікація** | автоматична публікація на GitHub Pages після кожного коміту |
| **SEO** | заголовок і опис сторінки, картинка для соцмереж, favicon, сторінка 404, сторінка подяки |

У шаблоні вже є 5 блоків-прикладів: перший екран, цифри, картки, FAQ і контакти з формою. Вони показують, як усе влаштовано, — Claude перебудує їх за вашим макетом.

## Як почати

1. Розпакуйте архів у папку з назвою **латиницею, без пробілів**, наприклад `C:\Projects\my-site`.
2. Відкрийте застосунок Claude → вкладка **Code** → оберіть цю папку.
3. Увімкніть режим планування (**Shift + Tab**) і вставте стартовий промпт:

```
Це стартовий шаблон лендингу. Прочитай CLAUDE.md.

Макет у Figma: [посилання на сторінку з макетом]
UI-кіт (кольори, стилі тексту, компоненти): [посилання на фрейм UI Kit]

Що зробити зараз:
1. Встанови залежності (npm install).
2. Заміни значення в src/styles/variables.css змінними з макета: кольори, стилі тексту, відступи.
3. Підключи шрифти з макета в src/layouts/Base.astro.
4. Запусти сайт локально і дай мені посилання.

Блоки поки не верстай. Спочатку покажи план, потім виконуй.
```

4. Далі збирайте блок за блоком, як в уроці 3:

```
Перебудуй Блок 1 за цим фреймом: [посилання на фрейм блоку]
Тексти й зображення винеси в src/content/home.json і додай поля в .pages.yml.
Використовуй тільки змінні з variables.css. Поки тільки десктоп.
```

Якщо в макеті більше блоків, ніж у шаблоні, Claude створить `Block6.astro`, `Block7.astro`… за тими самими правилами.

## Публікація на GitHub Pages

1. Створіть на GitHub порожній **Public** репозиторій (без README, .gitignore і license).
2. Промпт:

```
Підключи цей проєкт до мого репозиторію на GitHub: [посилання на репозиторій]
У site.config.mjs вкажи SITE_URL https://[логін].github.io і BASE_PATH /[назва-репозиторію].
Зроби перший коміт і відправ проєкт у репозиторій.
```

3. На GitHub: **Settings → Pages → Source: GitHub Actions**. Workflow-файл уже є в шаблоні.
4. Через 1–2 хвилини сайт з'явиться за адресою `логін.github.io/назва-репозиторію`.

Далі кожна зміна публікується промптом «Закоміть і відправ на GitHub».

## Форма заявок

Код скрипта вже готовий: `google-apps-script/Code.gs`.

1. Створіть бота через @BotFather, додайте його в групу для заявок і дізнайтеся chat ID групи (з мінусом) — як в уроці 5.
2. Створіть Google-таблицю → **Розширення → Apps Script** → вставте код з `Code.gs` → збережіть.
3. **Налаштування проєкту → Властивості скрипта**: `TELEGRAM_TOKEN` і `TELEGRAM_CHAT_ID`.
4. Оберіть функцію `testTelegram` → **Виконати**. У групі має з'явитися тестове повідомлення.
5. **Розгорнути → Нове розгортання → Веб-застосунок**: від імені «Я», доступ «Усі». Скопіюйте URL `/exec`.
6. Промпт:

```
Впиши в FORM_ENDPOINT у site.config.mjs цю адресу: [URL веб-застосунку]
Закоміть і відправ на GitHub.
```

7. Заповніть форму на живому сайті: заявка прийде в Telegram і з'явиться на аркуші «Заявки».

Змінили код скрипта — **Розгорнути → Керувати розгортаннями → олівець → Нова версія**. Нове розгортання не створюйте: зміниться адреса.

## Адмінка Pages CMS

Конфіг уже є: `.pages.yml`.

1. [app.pagescms.org](https://app.pagescms.org) → **Sign in with GitHub**.
2. Встановлення застосунку: **Only select repositories** → ваш репозиторій → Install.
3. Відкрийте репозиторій, гілка `main` — зліва з'являться розділи «Налаштування сайту» і «Головна сторінка».
4. Запросіть клієнта: налаштування репозиторію → **Collaborators** → email → Invite.

## Свій домен або піддомен

1. У DNS домену додайте запис **CNAME**: ім'я — ваш піддомен (наприклад, `solar`), значення — `логін.github.io`.
2. GitHub: **Settings → Pages → Custom domain** → введіть домен → Save.
3. Промпт:

```
Сайт тепер буде на домені https://[домен]. У site.config.mjs встанови SITE_URL на цей домен і BASE_PATH '/'.
Додай файл public/CNAME з доменом. Закоміть і відправ на GitHub.
```

4. Після перевірки DNS поставте галочку **Enforce HTTPS**.

## Перед здачею

- Замініть `public/favicon.svg` на свою іконку.
- Додайте картинку для соцмереж 1200×630 у `public/images/og-image.jpg` (або завантажте в адмінці: Налаштування сайту → SEO).
- Заповніть заголовок і опис сторінки в адмінці або в `src/content/settings.json`.
- Пройдіться по чек-листу готовності сайту.

Claude запускає їх сам, але про всяк випадок:

| Команда | Що робить |
|---|---|
| `npm install` | встановлює залежності |
| `npm run dev` | запускає сайт локально (localhost:4321) |
| `npm run build` | збирає сайт у папку `dist` |
